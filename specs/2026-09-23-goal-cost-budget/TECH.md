# Implementation notes

* Parse `--max-cost <USD>` deterministically at the slash-command boundary, ahead of the free-text objective. Store the numeric limit and draft's cumulative cost in branch-local `pi-goal-draft` entries. Seed the persisted goal's cost counter with that amount on confirmation; attribute the final confirmation response even though the draft is cleared inside the tool call.
* Add optional `maxCostUsd` and cumulative `usage.costUsd` to the goal file, with backward-compatible normalization. Update additive merge/conflict logic in GoalService so an accounting write from another session cannot erase cumulative cost.
* Use one cost gate in GoalAccounting alongside the token gate. Keep the existing `budget_limited` lifecycle, and adjust notifications, prompts, scheduling, status, and tweak resumption to name which limit was reached. Costs are doubles in USD in persistence (no rounding on accumulation); display rounded cents only.
* Subscribe to nested auditor assistant completions, send their cost to the parent goal meter, and stop the auditor when the cap is exhausted. Attribute Pi `usage` entries (e.g. cache warming) at observed turn/settle/shutdown boundaries and compaction summary usage at `session_compact`. Do not interpret a budget-triggered auditor abort as the user's Escape-to-bypass-audit choice.
* Test command parsing, invalid input, unpriced usage, draft confirmation/cancellation and restoration, nested auditor attribution and cancellation, budget transitions, two-limit behavior, tweak resumption, persistence/concurrency, and human/agent-facing documentation. Test using Node >=22.19 or 24 with the pinned Pi 0.87 development dependencies.
